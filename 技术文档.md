## 一、系统架构设计

### 1.1 整体分层

```
┌─────────────────────────────────────────────┐
│                  客户端层                    │
│   学生端 (PWA)              后台管理端       │
│   手机/平板浏览器           PC 浏览器        │
│   路由前缀: /               路由前缀: /mgmt  │
└──────────────────────┬──────────────────────┘
                       │ HTTPS
┌──────────────────────▼──────────────────────┐
│              Python FastAPI Server           │
├──────────────┬──────────────┬───────────────┤
│  Auth 模块   │  业务模块    │  AI 调用模块  │
│  登录/鉴权   │  作业/错题   │  多图批改     │
└──────────────┴──────┬───────┴───────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│                  数据层                      │
│   PostgreSQL              本地 /uploads/     │
│   (主数据库)              (图片，待迁移OSS)  │
└─────────────────────────────────────────────┘
                       │
┌──────────────────────▼──────────────────────┐
│               外部 AI 服务                   │
│   Anthropic Claude API  /  OpenAI 兼容接口  │
│   (动态切换，无需重启服务)                   │
└─────────────────────────────────────────────┘
```

### 1.2 技术选型（当前实现）

| 模块 | 选型 | 说明 |
|------|------|------|
| 后端框架 | Python FastAPI | 异步，AI 调用方便 |
| 数据库 | PostgreSQL | SQLAlchemy ORM |
| 前端框架 | Vue 3 + Vite | Composition API |
| UI 组件库 | Element Plus | 全局注册图标 |

| 图片存储 | 本地 `/uploads/` | 待迁移云存储 |
| AI | Anthropic / OpenAI | 后台动态配置切换 |

学生端与管理端在同一浏览器互不干扰：

| | 学生端 | 管理端 |
|--|--------|--------|
| Pinia Store | `useAuthStore` | `useAdminAuthStore` |

## 二、数据库设计

### 2.1 表一览

```
users                  用户表（学生 + 管理员）
subscriptions          订阅表（学科 + 有效期）
records                批改记录表（多图 + AI 结果）
mistakes               错题集表（独立存储，与 records 解耦）
llm_configs            LLM 配置表（支持多配置切换）
exercise_types         题型表（输出格式 + 排序）
exercise_type_prompts  Prompt 版本表（每题型多版本）
```

### 2.2 用户表 `users`

```sql
id            UUID PRIMARY KEY
username      VARCHAR(50) UNIQUE NOT NULL
password_hash VARCHAR(200) NOT NULL
name          VARCHAR(50)
role          VARCHAR(10)          -- 'student' | 'admin'
grade_level   VARCHAR(10)          -- 'junior' | 'senior'（学生用）
is_active     BOOLEAN DEFAULT true
created_at    TIMESTAMPTZ
```

### 2.3 订阅表 `subscriptions`

```sql
id            UUID PRIMARY KEY
student_id    UUID REFERENCES users(id)
subject       VARCHAR(20)          -- 'math'|'chinese'|'english'|'physics'|'chemistry'|'biology'
grade_level   VARCHAR(10)
start_date    DATE
end_date      DATE
is_active     BOOLEAN DEFAULT true
created_at    TIMESTAMPTZ
```

### 2.4 批改记录表 `records`

```sql
id                UUID PRIMARY KEY
student_id        UUID REFERENCES users(id)
subject           VARCHAR(20)
exercise_type_id  UUID REFERENCES exercise_types(id)  -- 可为空（通用批改）
image_url         TEXT                -- JSON 数组字符串，存多图 URL 列表
is_correct        BOOLEAN
ai_feedback       TEXT                -- JSON 字符串或 Markdown 文本
ai_thinking       TEXT                -- 解题思路（懒加载）
token_input       INTEGER
token_output      INTEGER
llm_provider      VARCHAR(20)
llm_model         VARCHAR(100)
created_at        TIMESTAMPTZ
```

**image_url 格式：**
```json
["/uploads/abc.jpg", "/uploads/def.jpg"]
```
兼容旧的单图字符串（前端用 `JSON.parse` 判断）。

### 2.5 错题集表 `mistakes`

```sql
id            UUID PRIMARY KEY
student_id    UUID REFERENCES users(id)
record_id     UUID                -- nullable，仅做参考，不做 FK 约束
subject       VARCHAR(20)
note          TEXT                -- 错误摘要（加入时自动生成）
status        VARCHAR(10) DEFAULT 'pending'   -- 'pending' | 'mastered'
retry_count   INTEGER DEFAULT 0
image_url     TEXT                -- 独立冗余存储（与 records 解耦）
ai_feedback   TEXT                -- 独立冗余存储
output_schema VARCHAR(20)        -- 'simple' | 'items' | 'essay'
created_at    TIMESTAMPTZ
mastered_at   TIMESTAMPTZ
```

**设计原则：删除 record 不删 mistake**。错题集在加入时完整复制 `image_url`、`ai_feedback`、`output_schema`，之后与 records 表完全独立。

### 2.6 LLM 配置表 `llm_configs`

```sql
id             UUID PRIMARY KEY
provider       VARCHAR(20)         -- 'anthropic' | 'openai'
model_id       VARCHAR(100)        -- e.g. 'claude-sonnet-4-6', 'gpt-5.6-sol'
api_key        VARCHAR(200)
api_base_url   VARCHAR(200)        -- OpenAI 兼容接口用（DeepSeek 等）
is_active      BOOLEAN DEFAULT false   -- 同一时间只有一个激活
price_input    FLOAT               -- 每百万 input token 价格
price_output   FLOAT               -- 每百万 output token 价格
price_currency VARCHAR(3)          -- 'CNY' | 'USD'
created_at     TIMESTAMPTZ
```

**已配置模型：**
- `claude-sonnet-4-6`（Anthropic）
- `gpt-5.6-sol`（OpenAI，推理模型）
- `deepseek-chat`（DeepSeek V3，CNY 计费）
- `deepseek-flash`（DeepSeek V4.1-Flash，CNY 计费）
- `deepseek-v4-pro`（DeepSeek V4-Pro，CNY 计费）

### 2.7 题型表 `exercise_types`

```sql
id               UUID PRIMARY KEY
subject          VARCHAR(20)
name             VARCHAR(50)
prompt_template  TEXT             -- 向后兼容保留，新版本改用 exercise_type_prompts
output_schema    VARCHAR(20)      -- 'simple' | 'items' | 'essay'
is_active        BOOLEAN DEFAULT true
sort_order       VARCHAR(5) DEFAULT '0'
created_at       TIMESTAMPTZ
```

### 2.8 Prompt 版本表 `exercise_type_prompts`

```sql
id                UUID PRIMARY KEY
exercise_type_id  UUID REFERENCES exercise_types(id)
version_name      VARCHAR(100)     -- e.g. 'v1 初版', 'v2 更详细'
prompt_template   TEXT             -- 含 {grade} {subject} 占位符
is_active         BOOLEAN DEFAULT false   -- 每个题型同一时间只有一个激活
created_at        TIMESTAMPTZ
```

**激活逻辑：** AI 批改时优先使用该题型下 `is_active=True` 的版本；若无激活版本，fallback 到 `exercise_types.prompt_template`。

## 三、API 接口设计

### 3.1 认证接口

```
POST /auth/login
Body: { "username": "...", "password": "..." }
Response: { "access_token": "...", "token_type": "bearer", "user": {...} }
```

### 3.2 学科接口

```
GET  /subjects/my                          获取我的订阅学科列表
GET  /subjects/exercise-types?subject=     获取学科下的题型列表
```

### 3.3 批改记录接口

```
POST /records/submit                       提交批改（multipart/form-data）
  fields: subject, files（多文件）, exercise_type_id（可选）
  返回: { id, is_correct, output_schema, result, subject, image_urls, image_url }

GET  /records/recent?subject=&limit=       最近记录列表（含 llm_model，北京时间）
GET  /records/:record_id                   获取单条记录详情（output_schema 从 exercise_types 表读取）
DELETE /records/:record_id                 删除记录（不删错题集）
POST /records/:record_id/thinking          获取解题思路（懒加载）
```

**注意：** `/recent` 路由必须定义在 `/:record_id` 之前，避免路由遮盖。

## 四、AI 调用层设计

### 4.1 动态配置加载

每次 AI 调用时从数据库读取当前激活的 `llm_config`，后台切换配置后立即生效，无需重启。

```python
def get_active_config(db) -> LLMConfig:
    return db.query(LLMConfig).filter(LLMConfig.is_active == True).first()
```

### 4.2 推理模型兼容

o 系列、gpt-5 系列等推理模型不接受 `max_tokens` 参数，只接受 `max_completion_tokens`。

```python
model_id = config.model_id.lower()
use_completion_tokens = any(model_id.startswith(p) for p in ("o1", "o3", "o4", "gpt-5", "gpt-o"))
if use_completion_tokens:
    response = client.chat.completions.create(**kwargs, max_completion_tokens=max_tokens)
else:
    response = client.chat.completions.create(**kwargs, max_tokens=max_tokens)
```

推理模型的 `reasoning_tokens` 会消耗大量配额，所有 schema 统一使用 `max_tok=16000`。

### 4.3 多图支持

`call_llm(config, prompt, image_url: str | list[str])` 接受单图或图片列表。

- **Anthropic**：构建多个 `{"type": "image", "source": {...}}` content block，再加 text block
- **OpenAI**：构建多个 `{"type": "image_url", ...}` content block，本地图片转 base64 data URL

多图时在 prompt 前追加说明：
```
以下共 N 张图片，请自行判断哪些是题目、哪些是学生的手写作答，然后进行批改。
```

### 4.4 输出格式（output_schema）

| schema | max_tokens | 解析方式 | 适用场景 |
|--------|-----------|---------|---------|
| `simple` | 16000 | 原始文本（Markdown） | 概要写作等需完整报告的题型 |
| `items` | 16000 | 提取 `[...]` JSON 数组 | 翻译题（多题） |
| `essay` | 16000 | 提取 `{...}` JSON 对象 | 书面表达作文 |

**simple schema 解析：**
```python
# 先尝试解析 JSON，失败则将原始文本作为 feedback 字段
match = re.search(r'\{.*\}', raw, re.DOTALL)
result = json.loads(match.group()) if match else {"is_correct": False, "feedback": raw, "hint": ""}
```
概要写作返回 Markdown 文本，JSON 解析失败，`result.feedback` 即完整 Markdown 报告。

### 4.5 Prompt 版本选取

```python
active_prompt = db.query(ExerciseTypePrompt).filter(
    ExerciseTypePrompt.exercise_type_id == exercise_type.id,
    ExerciseTypePrompt.is_active == True,
).first()
prompt_tpl = active_prompt.prompt_template if active_prompt else exercise_type.prompt_template
prompt = prompt_tpl.format(grade=grade, subject=subj)
```

### 4.6 费用计算（双币种）

```python
EXCHANGE_RATE = 6.7

def calc_cost(tok_in, tok_out, price_in, price_out, currency="CNY"):
    raw = tok_in / 1_000_000 * price_in + tok_out / 1_000_000 * price_out
    if currency == "USD":
        usd = round(raw, 4)
        cny = round(raw * EXCHANGE_RATE, 4)
    else:
        cny = round(raw, 4)
        usd = round(raw / EXCHANGE_RATE, 4)
    return {"cny": cny, "usd": usd}
```

`price_input` / `price_output` 单位与 `price_currency` 字段对应，存于 `llm_configs` 表。

## 五、权限与安全设计

### 5.1 认证方式

- JWT Bearer Token，无状态验证
- 学生端与管理端 Token 存不同 localStorage key，互不干扰
- 管理端接口通过 `user.role == 'admin'` 校验

### 5.2 科目权限校验

每次提交批改前：
1. 查 `subscriptions` 表，确认学生有该学科的有效订阅（`is_active=True` 且 `end_date >= today`）
2. 若无订阅返回 403

### 5.3 数据隔离

- 所有学生数据接口均过滤 `student_id == current_user.id`
- 错题集、批改记录均只能查/删自己的数据

### 5.4 防滥用

| 风险 | 措施 |
|------|------|
| 上传非图片 | 后端校验 Content-Type；OSS 侧格式校验 |
| 大文件 | 上传限制（存储层控制） |
| 越权访问 | 所有查询强制带 student_id 过滤 |

## 六、前端关键实现说明

### 6.1 image_url 兼容处理

`image_url` 字段可能是：
- 旧格式：普通字符串 `/uploads/xxx.jpg`
- 新格式：JSON 数组字符串 `["/uploads/a.jpg", "/uploads/b.jpg"]`

前端统一用以下函数处理：
```js
function firstImage(url) {
  try {
    const arr = JSON.parse(url)
    return Array.isArray(arr) ? arr[0] : url
  } catch { return url }
}
```

### 6.2 批改结果三种渲染模式

| 条件 | 渲染模式 |
|------|---------|
| `output_schema === 'essay'` | essay 模板（分数卡 + 逐句批注 + 修改版 + 范文） |
| `Array.isArray(result)` | items 模板（逐题卡片） |
| 其他 | simple 模板（`marked` 渲染 `result.feedback` 的 Markdown） |

### 6.3 essay 逐句标注算法

`buildSegments(original, errors)` 将原句和错误列表合并为带标记的文字段：
1. 按 errors[].text 在 original 中的出现位置排序
2. 未被标记的部分输出为 `type='plain'`
3. 被标记的部分输出为 `type='error'`（红色）或 `type='suggestion'`（蓝色）
4. 前端根据 type 渲染对应颜色高亮

### 6.4 output_schema 正确识别

`GET /records/:id` 不依赖 result 数据类型推断 schema，而是查询 `exercise_types` 表获取真实 `output_schema`：

```python
if record.exercise_type_id:
    et = db.query(ExerciseType).filter(ExerciseType.id == record.exercise_type_id).first()
    output_schema = et.output_schema if et else ("items" if isinstance(result, list) else "simple")
```

### 6.5 sessionStorage 缓存策略

提交批改后结果存入 `sessionStorage('last_record')`，ResultView 优先从缓存读取（避免重复请求）。缓存命中条件：`parsed.id === recordId`。未命中时回退到 `GET /records/:id`。

### 6.6 Markdown 渲染

`simple` schema 的批改结果使用 `marked` 库渲染：

```js
import { marked } from 'marked'

function renderMarkdown(text) {
  return marked.parse(text || '')
}
// 模板中：
// <div class="markdown-body" v-html="renderMarkdown(record.result.feedback)"></div>
```

样式覆盖 Outlook/默认样式，支持表格、标题层级、代码块、引用块等。

### 6.7 北京时间转换

后端存储 UTC，前端显示北京时间（UTC+8）：

```python
# 后端 /records/recent
"created_at": (r.created_at + timedelta(hours=8)).isoformat()
```
